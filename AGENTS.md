# Quran Repository Guidelines

## Product

Al-Quran web app: surah/juz reading (mushaf + pager modes), search, bookmarks,
per-ayah audio, offline PWA, and jadwal sholat with Kemenag calculation.

## Stack

- TypeScript / Next.js 16.3.0 App Router, `output: "export"` (fully static)
- Tailwind CSS v4 with a classic mushaf theme (cream paper default, sepia
  night mode via `data-theme`). **Intentional deviation from the System One
  contract** (root AGENTS.md): the owner asked for an old-school look —
  deep green `#1F5C3D` primary instead of blue, gold `#9A7B2D` ornaments,
  Georgia serif headings, 3px radius, no decorative shadows.
- Zustand + localStorage for all user state; no backend, no accounts
- Prayer times: `@masaajid/prayer-times` (Kemenag method), validated against
  `adhan` in unit tests
- Oxc lint/format, vitest, Playwright

## Data pipeline

Quran text lives in `public/data/` as split static assets, generated by
`pnpm data:fetch` (`scripts/fetch-quran-data.ts`):

- `public/data/surah/{1..114}.json` — per-surah ayahs (Uthmani Arabic,
  Kemenag Indonesian + footnotes, Saheeh International English)
- `public/data/search-index.json` — normalized Arabic + translations
- `public/data/juz-map.json` — first ayah of each juz
- `src/data/surah-index.ts` — typed metadata for all 114 surahs

Pages read per-surah JSON from disk at build time via `src/lib/quran.ts`.
Bismillah is stripped from ayah 1 of surahs other than 1 and 9; the reader
renders its own bismillah header.

## Verification

Run from this repository root:

- `pnpm run verify` (lint, typecheck, unit+integration tests, static build)
- `pnpm run verify:full` adds Playwright e2e against the exported `out/`

## Deployment

`./deploy.sh` builds `out/` and atomically swaps it into the Caddy web root
for quran.efektif.app with rollback on failure. `pnpm start` serves `out/`
locally.

Cloudflare Pages (static export via `wrangler.toml` /
`pages_build_output_dir = "out"`):

- Local / CLI: `pnpm deploy` (build + upload) or `pnpm deploy:pages` (upload
  only).
- Dashboard / CI build settings must stay static — never set the deploy
  command to `npx wrangler deploy` (that triggers Workers/OpenNext auto
  migration and fails on `output: "export"`):
  - Build command: `pnpm run build`
  - Build output directory: `out`
  - Deploy command (if custom): `pnpm run deploy:pages`
  - Framework preset: None / static (not Next.js Workers)

## Conventions

- This repository keeps **one** knowledge document: `AGENTS.md`. Do not add
  `README.md`, `docs/`, or other markdown knowledge files unless they are
  product artifacts already required by the project.
- Follow the Efektif root `AGENTS.md` for cross-repo boundaries. This file
  overrides root guidance for work inside this repository.
- Use manifests and package scripts as the runtime source of truth.
- Extend this file when new durable knowledge is needed.
